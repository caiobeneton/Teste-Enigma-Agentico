### Dependências e decisões

- Não há tarefa de implementação anterior. Preservar a stack aprovada: JavaScript e JSX, módulos ES, React/Vite no workspace `web` e Express no workspace `api`. Todos os pacotes do projeto serão privados, evitando publicação acidental no npm.
- Um `package.json` privado na raiz declara `workspaces: ["web", "api"]`. Cada workspace tem manifesto próprio e `type: "module"`; a raiz também declara esse tipo. Um único `package-lock.json` na raiz fixa a árvore e os vínculos locais. Instalação e comandos documentados partem da raiz.
- Fixar dependências diretas sem `^`, `~` ou `latest`: `react` e `react-dom` **19.3.1** no `web`, `vite` **8.3.8** e `@vitejs/plugin-react` **6.3.0** como dependências de desenvolvimento do `web`, e `express` **5.3.0** no `api`. Estas versões foram consultadas no registro oficial npm em 16/11/2026 com `npm view <pacote> version engines peerDependencies --json`. O plugin React 6.3.0 declara Vite `^8.0.0`; seus peers de compiladores React são opcionais e não serão instalados nem ativados. Vite e plugin aceitam Node `^20.19.0 || >=22.12.0`, Express aceita `>=18`, e React DOM exige React `^19.3.1`: a combinação proposta é compatível com Node 24 atualizado. O lockfile será gerado pelo npm, nunca escrito manualmente.
- A referência de runtime é **Node 24.22.3**, patch atual da família 24 na fonte oficial consultada em 16/11/2026, publicado em 11/11/2026. Declarar `engines.node: ">=24.22.3 <25"` nos manifests e uma `.nvmrc` com `24.22.3`; esse arquivo registra a versão e não instala nem altera o Node global. A versão npm efetivamente incluída no runtime usado deve ser registrada nas evidências e no tutorial. Não prometer que uma faixa `engines` se mantenha atualizada por si só.
- A máquina começa com Node 24.11.1. Validar com a distribuição oficial portátil Windows x64 de Node 24.22.3 em um diretório específico dentro de `TEMP`, conferindo seu SHA256 contra `SHASUMS256.txt`. Acionar o executável portátil e seu npm, ou ajustar `PATH` somente para o processo de verificação, sem instalador, alteração persistente de ambiente ou substituição do Node global. Falha no download ou checksum impede atestar a validação com runtime atualizado.
- Usar o plugin React oficial, com `defineConfig({ plugins: [react()] })`, para transformação JSX automática e Fast Refresh no desenvolvimento. A pequena configuração em `web/vite.config.js` é explícita e didática. JSX sem plugin seria possível em configurações específicas, mas dispensaria a integração React oferecida pelo plugin e acrescentaria diferenças desnecessárias ao percurso de aprendizado. Não introduzir TypeScript, Babel configurado à parte, React Compiler, SWC, router ou bibliotecas de componentes nesta tarefa.

### Contratos, invariantes e limites

O contrato do frontend nesta tarefa é gerar `web/dist/index.html` e seus recursos reais com `npm run build`, e apresentar a pergunta inicial por React em desenvolvimento ou preview. `preview` serve somente para inspeção local do build e não constitui o servidor de produção integrado. O contrato da base de API é permitir importação ES e criação de uma instância Express sem escutar em uma porta ou efetuar efeitos externos. A verificação dessa base deve executar a importação e chamar a fábrica, além da checagem sintática; uma dependência apenas listada no manifesto seria evidência insuficiente.

Não acrescentar proxy, `/api/health`, listener Express, arquivos estáticos, fallback SPA ou testes de integração: esses resultados pertencem a 1.2. Não acrescentar variáveis de aplicação, scripts de migração/testes ou persistência: pertencem a 1.3 e aos blocos seguintes. A pergunta renderizada é uma prova mínima de montagem React, não aceite funcional de `terminal-entry` ou conclusão de 6.1.

4. Executar `npm run build` e verificar saída HTML e recursos em `web/dist/`. Inspecionar o frontend em navegador quando disponível para confirmar a montagem da mensagem e a ausência de erros de módulo. Distinguir inspeção visual de teste automatizado e de teste HTTP.

Riscos tratados: Node global antigo (runtime portátil verificado), instalação de binários nativos transitivos do Vite em Windows (validar instalação e build reais, sem trocar silenciosamente a stack), divergência de React/React DOM (mesma versão exata), instruções de uma API ainda não executável (explicitar fábrica sem listener) e tutorial que dependa de arquivo gerado previamente (reprodução em cópia limpa e lockfile versionado).
